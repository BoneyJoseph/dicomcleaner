# BNEL Dicom Cleaner

Portable Windows app for reviewing and de-identifying CT, MR and spatial/deformable registration DICOMs. This is a research validation release, not a certified de-identification service or diagnostic viewer. Validate representative scanner exports and downstream registration software before real disclosures.

## Run on Windows

Extract the entire `BNEL-Dicom-Cleaner-0.1.0-Windows-x64.zip` to a writable folder. Open `BNEL Dicom Cleaner.exe` inside it. Keep `app` and `runtime` alongside the executable. No Java installation, terminal, installer, or internet connection is required. The build is unsigned; Windows may show its usual downloaded-app warning.

1. Import a folder or add files. Folders are scanned recursively. Select a patient, study, series or individual instance. Different patient identities are never silently merged.
2. Inspect any individual instance in Original. The All original metadata tab automatically indexes the union of tags in every loaded file, including nested and private tags. Select a tag for every file's value, including explicit absent entries. Search complete values; filter differences/missing tags. All cleaned metadata provides the same view after cleaning. The individual-instance view supports complete values and binary inspection/export. Compare files also lists differences and missing tags.
3. Enter unrelated research Patient Name and Patient ID, and a synthetic date. Patient Name/ID fields reset on every import. Identifier rules offers Remove, Default, Random and Custom choices for other text identifiers, and remembers those choices. Scan labels lets you review all original labels per series and enter clean labels such as T1-weighted, FLAIR or a verified Sequence Name. These approvals reset when files are added or removed. Choose Clean selected. The progress bar reports the current stage and files completed. Adding files or changing cleaning options invalidates the cleaned batch and its reviews.
4. Review every cleaned instance and every frame. Use window/level and zoom to inspect the pixels. Draw blackout rectangles and Apply blackout to all frames when needed. Rectangles affect the staged copy of the selected instance only. Review the result again. The two approval boxes must reflect your actual assessment, including recognizable facial anatomy in a 3D reconstruction. Blackout does not automatically deface a volume.
5. Export cleaned becomes available after all instances are approved and reference warnings resolved. Choose a new output folder or ZIP outside the source folders. Originals are never overwritten.

## Metadata policy and embedded identifiers

The bundled DICOM PS3.15 2026d Table E.1-1 supplies basic confidentiality actions. The app additionally removes private/unknown tags, overlays, history, signatures, arbitrary opaque payloads and unrestricted text recursively in every file. Comments, descriptions, protocol text, long UT/LT/ST/UC values, paths, and mixed text are cleared or removed in full, not merely searched for one patient name. Unrecognized CS values are also cleared; a small list of necessary technical values is retained. This deliberately loses descriptive/protocol metadata and some nonessential coded fields.

A second pass gathers source identifiers from every selected file, then rejects surviving matches in retained text and suspicious email/URL/path/identifier patterns. The check ignores punctuation, case and diacritics for known-identifier matches; components shorter than four characters are not used because they create pervasive false matches. It is a secondary check, not a claim to detect all PHI or hidden encodings. Unknown sequences and private binary objects are removed; only documented image/LUT/registration numeric payload types are retained. Arbitrary steganography in numeric or pixel payloads is outside scope.

Essential research metadata is an optional allowlist for classic CT, classic MR and REG objects. It retains core image geometry, pixel decoding fields, quantitative acquisition values (e.g. TR/TE/TI), validated Scan Options and MR Acquisition Type, and your reviewed scan labels. It is not a blanket deletion of every optional DICOM field. It currently rejects enhanced/secondary-capture objects with an instruction to use the broader policy, because their required modules differ. Validate your downstream software before adopting this option.

Identifier rules covers other names/physicians/operators, addresses/telephone/email, IDs/accession/clinic numbers, institution/location, manufacturer/model/device and clinical-trial fields. Default uses REDACTED; Random generates fresh per-job placeholders consistently for repeated values; Custom accepts a short non-identifying placeholder. Rules only replace eligible text VRs. Numeric or enumerated patient characteristics such as smoking status are removed/emptied. UIDs and dates use their own typed handling. Never enter real identifying information into a persisted custom placeholder.

All nonstructural UIDs are remapped consistently within one cleaning job, including nested references and frames of reference. The app verifies pixel payload and geometric attributes after metadata cleaning, recreates file metadata and the preamble, and checks source hashes. CT/MR and their REG objects must be cleaned together. Missing REG references block cleaning. Other external references require an explicit warning acknowledgment.

Default dates are removed, emptied or replaced with the chosen synthetic date; time fields are removed, emptied or set to zero. Date shifting is an explicit custom exception that preserves intervals and times. It requires an in-memory note and is **not represented as Safe Harbor compliance**. No exception note, patient name, ID, source path, original UID map or review approval is saved to preferences.

HIPAA Safe Harbor applies to identifiers wherever they occur, including free text, and includes an actual-knowledge condition. Software configuration alone does not establish compliance. Burned-in text, recognizable anatomy, filenames, recipient context and any exceptions need assessment. Head CT/MR may require an independently validated facial-defacing workflow before import. The app has no automatic OCR or automatic 3D defacing, and cannot certify a disclosure. See [HHS de-identification guidance](https://www.hhs.gov/hipaa/for-professionals/special-topics/de-identification/index.html) and [DICOM PS3.15](https://dicom.nema.org/medical/dicom/2026d/output/chtml/part15/chapter_E.html).

## Export and preferences

Preserve imported hierarchy is on by default. Directory nesting and sibling grouping are preserved using neutral folder/file names. Retain original names requires explicit review because names can identify a patient. Multiple import roots are placed in separate neutral root directories. An optional DICOMDIR indexes the exported instances; its standard requires at most eight path components, each 1–8 uppercase letters/digits/underscores. Use neutral names or disable hierarchy if a source tree is too deep. ZIP includes the same tree and optional DICOMDIR.

A review report contains counts, policy operations and exception status without source identifiers. Export uses a temporary transaction and does not leave a final destination after cancellation or a validation failure. Staged data is cleared when the session is cleared or the app closes normally. An abrupt crash can leave `bnel-cleaner-*` folders in the current user's temporary directory; handle them under the same policy as medical imaging data. Deletion is ordinary filesystem deletion, not secure erasure.

Identifier rules, options, synthetic date, window dimensions and split positions are stored in `BNEL-settings.properties` next to the executable. Do not put identifying dates into the synthetic-date field. A read-only app folder prevents preferences from being saved. Patient replacement values and review approvals are intentionally not remembered.

## Supported scope and limitations

CT/MR, enhanced and legacy-converted enhanced CT/MR, spatial/deformable registration and selected secondary-capture SOP classes are accepted. Unsupported classes remain inspectable but cannot be cleaned/exported. Encapsulated documents, SR, SEG, RTSTRUCT and presentation-state cleaning are outside this release. Separate overlays are removed; embedded overlay bits require external cleanup. Pixel data is preserved in its original transfer syntax unless manually redacted. A decoder failure blocks review and approval. Compressed JPEG/JPEG-LS streams are checked for comments, EXIF/other application blocks, thumbnails and trailing hidden data; nonessential embedded metadata blocks are rejected rather than copied. RLE unused header slots must be empty. Other compressed formats, including JPEG 2000, require trusted external DICOM decompression before cleaning in this release. This check does not attempt to detect pixel steganography. Blackout supports integer monochrome images; color-image redaction must be done externally. Metadata inspection includes every parsed element; binary values have a 64 KB hex preview plus an unrestricted full-element export.

This app keeps the local import / inspect / clean / redact / review / folder / ZIP / DICOMDIR workflow. It does not implement PACS C-FIND/C-MOVE/C-STORE, media burning, cloud upload, automatic volume defacing or retention of identifying institution/device/private information. The legacy upstream application remains unchanged in the repository.

## Build and verification

A JDK 17+ and Python 3.12 are needed only on the build machine. Run `python standalone/build.py`. Run `python standalone/build.py --gui-test --package` on Windows for a portable image and ZIP. The workflow builds on Windows 2022 with Temurin 21 and tests the packaged GUI launcher. Target Windows x64.

PixelMed 20260916 archives are pinned by SHA-256 and fetched only during the build. Only PixelMed, its image codec/provider and vecmath are bundled, along with license notices and the Java runtime's legal directory. The app has no networking code or cloud credentials. The responsive interface uses soft gray/blue surfaces, native window maximization, adjustable split panes, wrapped controls, and a stacked comparison layout in narrow portrait windows. Tables render visible rows and accept precise wheel scrolling. Windows handles monitor DPI scaling; font sizes are logical units rather than 4K physical pixels. Synthetic tests cover CT/MR/REG UID relationships, source immutability, mixed/nested/late-added text, pixel and geometry preservation, date replacement/shifting, blackout, DICOMDIR references, folder/ZIP export, rollback and saved settings. These tests are not a substitute for external DICOM conformance, privacy and clinical workflow validation.
